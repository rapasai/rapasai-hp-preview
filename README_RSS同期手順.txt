RapasAI Lab｜note記事タイトル・表紙画像の同期手順

【基本方針】
正本：rapasai_series_04_08_pdf_covers_update.zip。
連載の本棚（第0回〜第9回）とおすすめ3枠を維持します。
このZIPには assets/covers フォルダを同梱していません。

【重要：初回同期前の扱い】
この配布ZIPの articles.json は従来の画像参照を保持しています。
既存GitHubリポジトリに置かれた表紙は、最初の同期が成功するまで残してください。
同期が成功した場合にのみ、すべての表紙URLをnoteの画像URLへ切り替え、旧coversを削除します。
全21記事の画像が取得できなければ、記事データや旧表紙を変更しません。
従って、これを新しい空のリポジトリへ単独で入れた場合、初回同期前には表紙が表示できません。

【導入手順】
1. このZIPを解凍し、中のファイルを既存GitHubリポジトリへアップロードします。
2. 最初は既存の assets/covers フォルダを削除しません。
3. GitHub Actions の「note記事情報・表紙画像を同期」を手動実行します。
4. 成功したら、articles.json の全21件の cover が https:// から始まり、assets/covers がGitHubから消えたことを確認します。
5. 公開サイトの「おすすめ記事」「連載の本棚」「第9回」「表紙画像」を確認します。

【自動更新】
1日4回、RSSから既存記事の正式タイトル・投稿日・表紙を確認します。
RSSに掲載されない記事は公開ページのOGP画像を取得します。
noteのCDN画像を実際に取得できたか確認してから更新します。
公開日の取得元がRSSにない古い記事は、既存の登録日を維持します。
未登録の新記事を勝手にカテゴリへ追加しません。

【検証状況】
XMLテスト及びローカル検証は可能ですが、この実行環境はnoteへの外部通信ができません。
GitHub Actions で実RSS・画像取得がPASSした場合にのみ外部取得を確認済みと扱います。
日本語ファイル名と本文はUTF-8。ファイル名を英語に変更して文字化けを回避しません。
